# Release security review

The release workflow runs the official WordPress Plugin Check action without global error/warning exclusions. Any inline PHPCS annotations describe a specific reviewed operation:

- Admin GET parameters choose a view, filter, page or escaped status notice. They do not write state, and the screen checks administrator capabilities. Requiring a mutation nonce for these read-only selections would not add a protection boundary.
- Product-branding save/error notices additionally require a nonce for the current administrator session; redirects generate it with `wp_create_nonce` and rendering verifies it with `wp_verify_nonce`. Missing, invalid or structured notice values are ignored without preventing normal editor access. Ordinary view/filter selection remains read-only.
- AJAX handlers explicitly verify `abmm_admin` nonces and then check `manage_options` before reading or writing menu data. Form handlers use `check_admin_referer` and capabilities.
- JSON menu data is size/depth checked, decoded, structurally validated and sanitized by menu field before persistence. Profile and branding arrays use their dedicated field sanitizers rather than flattening structured values into text.
- Upload imports check file errors, name/extension, size and `is_uploaded_file` before reading the temporary file. Content is validated as JSON and sanitized before persistence; no uploaded PHP is executed.
- Upload metadata must be a single-file record with string name/temporary path and integer size/error fields before sanitization or filesystem access. Structured or incomplete fields return a controlled 400 response.
- Portable import format versions must be the supported integer or its exact string representation, and menu titles must be nonempty strings after text sanitization. Decoding JSON alone never constitutes sanitization.
- CLI exports emit portable JSON to standard output without writing any server-side files. The old export `--file` argument fails explicitly; operators can redirect output to a private destination with restrictive permissions. Browser/REST exports retain administrator checks, and existing import files keep their format.
- Prepared MySQL GET_LOCK/RELEASE_LOCK queries serialize every active/archive collection mutation, including imports and backup recovery. Lock results must never be cached. An unavailable or busy lock returns an error rather than bypassing concurrency protection. Nested operations reuse the owned lock; the outer operation refreshes option caches after acquiring it.
- Imports and recovery create a retained recovery point before replacing data; a failed backup write aborts the mutation. Recovery requires the current collection revision. Backup listing, export and restore require administrator capability and a directly verified AJAX nonce. Listing exposes metadata rather than private menu contents. Five recovery points are retained; these are not full-site backups.
- Widget wrappers are passed through `wp_kses_post`; URLs, labels and attributes use context-specific escaping. Bundled SVG markup uses an explicit allowlist.
- Uninstall cleans site-local options and recovery drafts across the current network's multisite blogs in batches of 100, restoring the original blog context after each switch, including failures. Deactivation retains menu data. Other networks' site data and network options remain intact. Globally shared onboarding metadata is retained whenever another network exists. Unrelated site, network and user data is preserved. A dedicated disposable network test exercises actual create/reload/render isolation and uninstall, alongside single-site, denied-access and 205-site pagination harness tests.
- Archive confirmation text uses the localized admin string map; positional substitutions happen before HTML escaping. Translation markup and menu-title markup are rendered as text, and cancellation returns keyboard focus without mutating a menu.

This review is scoped to the initial public distribution. It is not a guarantee against all vulnerabilities. Report concerns using SECURITY.md and verify client-specific theme/plugin combinations on staging.
